# `verify` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `jig verify <commit|range> [--on <base>]` replays refactor commits in the sandbox and says whether each matches its recorded command, without touching the repo.

**Architecture:** Extract the export → run → report → checks → capture steps of `runImage` into one `replay` function; `runImage` and the new `verifyCommits` both call it. Verify reads the commit's trailers with git, replays on the parent (or `--on` base), and compares trees and recorded trailers. Output is one JSON object, `urn:jig:verify:1`.

**Tech Stack:** Swift 6.4.2 (swift-testing), git, the existing sandbox packages, the probe image (Node 26, TypeScript).

**Spec:** `docs/superpowers/specs/2026-11-18-verify-design.md`

## Global Constraints

- Every shell call goes through `nux` (see `nux help`); no Bun anywhere (`AGENTS.md`).
- Swift toolchain: `~/.local/share/swiftly/toolchains/6.4.2/usr/bin` (not on PATH); Node: `~/.local/share/node/node-v26.13.1-linux-x64/bin`.
- `verify` never writes the repo's work tree, index, refs or config; works with a dirty work tree.
- No built-in timeout. Interruption behaves as for a run (sandbox cleanup, temp dirs removed, exit 130/143/129 with the INTERNAL output:1 failure).
- Verdicts exactly: `identical`, `same-effect`, `different`, `failed`, `skipped`, `invalid`.
- Output schema URN exactly `urn:jig:verify:1`; pre-replay errors use `urn:jig:output:1` (`errorJSON`), exit 1.
- Do not mention in docs/summaries: symlinks created by images; publishing-stage topics (`AGENTS.md`).
- Tests: `sh scripts/test-swift.sh` (all packages) must stay green; existing run behaviour unchanged.

## Review Focus

1. A commit whose message was amended by hand so the trailer block is no longer last (e.g. a `Signed-off-by` paragraph added after) — read only git's parsed trailers; if `Refactor-Command` is missing there, it is `skipped`/error, never a guess. Test in Task 2.
2. A root commit (no parent) or a merge commit given as `<commit>` — clear `INVALID_ARGS` error with instructions; in a range, `skipped` with a reason. Test in Task 2 (unit) and Task 4 (integration for the root commit).
3. A range where every commit is hand-written — `ok: false` (nothing verified), exit 1, all `skipped`. Test in Task 4.
4. Verify run from a subdirectory or with `--repo` pointing at a subdirectory, with a dirty and staged work tree — results the same, and `git status --porcelain`, `HEAD`, `git rev-parse --all` and the index file bytes unchanged afterwards. Test in Task 4.
5. A replay whose image now fails (e.g. probe `fail`) — verdict `failed` with `code` and `instructions`, other commits in the range still verified. Test in Task 4.

**Interfaces:**
- Produces (Report):
  ```swift
  public struct RecordedCommand: Equatable, Sendable {
    public var image: String; public var args: [String]
    public var kind: String; public var status: String; public var effect: String; public var subject: String
  }
  public enum Verdict: String, Sendable { case identical, sameEffect = "same-effect", different, failed, skipped, invalid }
  public struct Mismatch: Equatable, Sendable { public var field: String; public var recorded: String; public var replayed: String }
  public struct CommitVerification: Equatable, Sendable {
    public var commit: String; public var verdict: Verdict
    public var command: RecordedCommand?; public var replayedEffect: String?
    public var filesDiffering: [String]; public var mismatches: [Mismatch]
    public var code: ErrorCode?; public var reason: String?; public var instructions: String?
  }
  /// `treesEqual` is nil with `--on` (trees are not compared).
  public func verdict(recorded: RecordedCommand, replayed: Report, treesEqual: Bool?) -> (Verdict, [Mismatch])
  public func verifyJSON(_ results: [CommitVerification], on: String?) -> (json: String, ok: Bool)
  public func parseRecordedCommand(json: String, kind: String, status: String, effect: String, subject: String) throws -> RecordedCommand
  ```
- Produces (Git):
  ```swift
  public struct CommitTrailers: Equatable, Sendable { public var parents: [String]; public var subject: String; public var trailers: [String: String] }
  public func readCommitTrailers(_ git: Git, _ commit: String) throws -> CommitTrailers
  ```
  Uses git's own trailer parsing (`git log -1 --format=...%(trailers:only,unfold)...` or `git interpret-trailers --parse`), so only the last trailer block counts. A key repeated → the last value.

### Task 4: `verifyCommits`, main wiring, integration tests

**Files:**
- Create: `swift/cli/Sources/RefactorCLI/Verify.swift`
- Modify: `swift/cli/Sources/jig/main.swift`, `swift/cli/Tests/IntegrationTests/probe/probe.ts` (new mode), `swift/cli/README.md`, root `README.md` usage section, `TODO.md`/`IDEAS.md` (mark verify done where listed)
- Test: `swift/cli/Tests/IntegrationTests/VerifyTests.swift`

**Interfaces:**
- Consumes: Task 1 `VerifyArgs`, Task 2 types and `readCommitTrailers`, Task 3 `replay`.
- Produces:
  ```swift
  public func verifyCommits(repo: String, target: String, on: String?, sandbox: any Sandbox) throws -> [CommitVerification]
  ```
  Single commit: missing trailers, root or merge commit → throw `INVALID_ARGS` with instructions. Range: `git rev-list --reverse --no-merges <range>`, those cases → `skipped` with `reason`; bad command JSON → `invalid`; any `RefactorError` from resolve/replay → `failed` with `code`/`instructions` and continue. `filesDiffering`: `git diff-tree -r --no-renames --name-only -z <replayed> <commit's tree>`. No `assertClean`. Main prints `verifyJSON(...).json` and exits 0 when `ok`, else 1.
- Probe mode `random`: writes `r.txt` with random content, reports a fixed effect `{op:"probe",mode:"random"}`.

- [ ] **Step 1: Write failing integration tests** (use the existing Helpers to build the probe/binary and make temp repos):
  `verifyFreshRunIsIdentical` (run probe `write a.txt`, verify HEAD → exit 0, verdict identical, empty filesDiffering, recordedEffect == replayedEffect);
  `verifyHandEditedCommitIsDifferent` (amend the commit with an extra edit in `a.txt`, keeping the message → effect same, tree differs → `same-effect`, `filesDiffering == ["a.txt"]`, exit 1);
  `verifyRandomIsSameEffect` (probe `random`);
  `verifyRangeSkipsHandWritten` (hand commit, probe commit, hand commit; `verify base..HEAD` → skipped, identical, skipped; ok);
  `verifyRangeAllHandWrittenIsNotOk` (Review Focus 3);
  `verifyRangeContinuesAfterFailure` (Review Focus 5: a commit whose recorded command is edited to `fail` via amend → `failed` with code; the next one still `identical`);
  `verifySingleWithoutTrailersErrors`, `verifyRootCommitErrors` (Review Focus 2; output:1 error, `INVALID_ARGS`);
  `verifyOnNewBaseSameEffect` (run probe `write a.txt` on X; make another base Y with an unrelated file; `verify <commit> --on Y` → same-effect, ok);
